# ETL — בסיס נתונים מאוחד לרשויות המקומיות (למ"ס)

צנרת שמאחדת את קבצי "הרשויות המקומיות בישראל" של הלמ"ס, **2003–2024 (22 שנים)**, לבסיס נתונים אחד.
כל הרשויות נשמרות (נדרש לחישוב בנצ'מרקים ארציים ולפי אשכול חברתי-כלכלי);
רשויות האשכול (גליל מזרחי/מערבי) מסומנות לפי `eshkol-matching/eshkol_mapping.xlsx`.

```bash
pip install -r etl/requirements.txt
python -m etl.build          # הכול לפי הסדר, כ-12 דקות; נעצר אם הבדיקה הבלתי-תלויה נכשלת
python -m pytest tests       # בדיקות
python -m etl.review_export  # נתונים לדף הבקרה (review/)
```

`etl.build` מריץ: `etl.run` (שלבים 0–2) → `etl.gold` (יחידות, עובדות, רשויות) → `etl.benchmarks`
(קבוצות השוואה) → `etl.audit` (בדיקה בלתי-תלויה מול קבצי המקור) → `etl.release` (המסד המפורסם).

## התוצר: `data/release/`

המסד עצמו, עם תיעוד מלא: [`data/release/README.md`](../data/release/README.md) (טבלאות, מושגים, בעיות ידועות,
תוצאות הבדיקה, מילון עמודות). לסוכני AI: [`AGENTS.md`](../AGENTS.md). פתיחה מתועדת ב-DuckDB:
`from etl.db import connect; con = connect()`.

`data/gold/` היא שכבת ביניים שנבנית מחדש בכל ריצה ואינה נשמרת ב-git; כל מה שבה זמין ב-`data/release/`.
הבדיקה הבלתי-תלויה: `data/qa/audit.json` (ופירוט ב-`audit_breaks.csv`, `consistency_violations.csv`, `mixed_scale.csv`).

## ממצאים חשובים בנתוני המקור

1. **`p_libud_2019.xlsx` הוא בפועל קובץ 2022** (זהה תא-לתא ל-`p_libud_22.xlsx` אחרי הסרת שתי עמודות שנוספו).
   מוחרג. נתוני 2019 נקראים מ-`2019.xlsx`.
2. **סמלי מועצות אזוריות**: עד 2023 דו-ספרתיים (הגליל העליון `01`), מ-2024 `5500+n` (`5501`).
   מנורמל לסכמת 2024. בלי זה ראש פינה (`26`) מתנגש במטה יהודה (`26`).
3. **שלושה מבני קבצים**: 2003–2013 — גיליונות נפרדים (עיריות+מ"מ / מ"א), כותרת בשורה 0;
   2014–2015 — אותו מבנה, כותרת בשורה 1; 2016+ — גיליון מאוחד עם 3–5 שורות כותרת.
   ב-2020+ אין תאים ממוזגים: תווית קבוצה כתובה באמצע בלוק שגבולותיו מסומנים ב-borders,
   ולכן הטווח משוחזר מהגבולות (`etl/headers.py`).
4. **גיליונות התקציב 2003–2008 ללא עמודת סמל**: השורות מקושרות לרשויות של אותה שנה לפי שם בלבד
   (חלש יותר — כל קישור מתועד ב-`data/qa/name_only_links.csv`). כל 1,520 הקישורים התאימו בשם מדויק.
5. **תקופת נתון ≠ שנת קובץ**: לכל עמודה נשמר `data_period` (למשל בקובץ 2024 השכר הוא 2023, החינוך תשפ"ד).
   חלק מהקבצים מכילים שתי שנים של אותו מדד (ארנונה 2015 ו-2016 בקובץ 2016).
   נתונים סטטיים חוזרים בכמה קבצים (שימושי קרקע 2013 בקבצי 2014–2020) — ייפתר בשלב 3 לפי `data_period`.
6. **ערכים חסרים**: ב-2003 וב-2008 הלמ"ס השאירה תאים ריקים (אין `-` או `..`), כך שאי אפשר להבחין
   בין "אין מקרים" ל"אין נתון".
7. **מספרים פגומים**: עמודת "חיוב ארנונה לקרקע תפוסה במפעל עתיר שטח" ב-2014–2016 מכילה ערכים כמו
   `569.453.0` (37 תאים, כולל חצור הגלילית, קצרין, עין קנייא). נשמרו ריקים עם דגל `malformed_number`.
8. **שורות סיכום של הלמ"ס**: ב-2022 שורת "כלל ארצי" של "הכנסות לנפש" היא *סכום* ערכים לנפש (2.4 מיליון) —
   אין להשתמש בה כבנצ'מרק כמות שהיא.
9. **סכום הרשויות < "כלל ארצי"** בכ-60–80 אלף נפש בכל שנה (אוכלוסייה שאינה בתחום רשות מקומית).
   "כלל ארצי" הרשמי ≠ סכום/ממוצע הרשויות — שני הבנצ'מרקים יוצגו בנפרד בשלב 4.
10. **מבנה התקציב השתנה ב-2017** (תקבולים/תשלומים "לפי פרקי תקציב" ו"לפי סוג ההכנסה"). רוב סדרות
    התקציב נשברות בין 2016 ל-2017; גישור ביניהן הוא החלטה מתודולוגית ולא נעשה אוטומטית.
11. **המדד החברתי-כלכלי** קיים בכל 22 השנים בארבעה ניסוחים שונים, שאוחדו דרך
    `etl/config/label_synonyms.yaml`. מהדורת המדד משתנה (2003, 2006, 2008, 2013, 2015, 2017, 2019, 2021);
    בקבצי 2003–2004 המהדורה לא מצוינת — תיקבע מהנתונים בשלב 3.

## יחידות — הוחלו לפי החלטות דף הבקרה

25 החלטות נשמרו ב-`etl/config/unit_decisions.yaml` (9 המרות, 16 ללא שינוי) ומוחלות בשלב 2ב לפי
(מדד, שנת קובץ). הערך כפי שפורסם נשמר לצד הערך המתוקנן (`observations.value_published`, `unit_factor`). עיקרי הממצאים:

* **אוכלוסייה / גברים / נשים**: באלפים עם ספרה עשרונית אחת ב-2003–2017 (32.9 = 32,900±50), מוחלט מ-2018.
  המרה ×1000 לא משחזרת דיוק.
* **2018 גברים/נשים**: הכותרת אומרת "(אלפים)" אבל הערכים מוחלטים — שגיאת כותרת של הלמ"ס.
* **יחס גבייה בארנונה למגורים (%)**: ב-2022 נשמר כשבר (0.75) ולא כאחוז (75).
* **אוכלוסייה בשימושי קרקע**: "סוף 2013" באלפים, "סוף 2021" מוחלט.
* **שטחי חיוב ארנונה לפי סוג נכס**: ב-2007–2016 גבוהים בערך פי 100 מהשנים האחרונות — לבדיקה.
* שינויים קטנים מ-×10 (למשל ל-1,000 מול ל-100,000) לא מזוהים אוטומטית — רק דרך שינוי בתווית.

## איך לבדוק את מיפוי המדדים

`column_map_DRAFT.csv` — שורה לכל עמודת מקור. עמודות מפתח:
`indicator_id`, `levels` (הכותרת המקורית), `matched_to`, `match_method`
(`exact` → `unit_variant` → `leaf` → `tokens` → `fuzzy` ≥0.85 → `new`),
`corr_with_newer_year` (מתאם Spearman עם אותו מדד בשנה החדשה הבאה, לפי סמל רשות),
`review_needed` / `review_reason`.

**בקרת נתונים**: התאמות לפי דמיון תווית נדחות כשהערכים סותרים אותן (Spearman מול השנה הקרובה מתחת
לסף). למשל "מכוניות פרטיות - שיעור ל-1,000 תושבים" ≠ "שיעור פטירות מתוקנן ל-1,000 תושבים" (ρ=−0.55).
הדחיות מתועדות ב-`data/qa/match_guard_rejections.csv`. שיעורי שינוי שנתיים פטורים (אין להם רציפות מטבעם).

**החלטות מיפוי**: לא נשמרו עדיין (`etl/config/mapping_decisions.yaml` ריק) — המיפוי האוטומטי בשימוש.
לכל ערך במסד יש `mapping_confidence` (high / medium / low) לפי הראיות: שיטת ההתאמה ומתאם הערכים עם השנה הסמוכה.
עמודות medium/low מוצגות לבדיקה בדף הבקרה.

**גרסאות מתוקנות**: כשכמה קבצים מדווחים על אותו (מדד, רשות, שנה), נבחר הקובץ החדש ביותר שיש בו ערך.
ערכים שונים מקבצים אחרים: `data/release/parquet/observation_revisions.parquet` (ופירוט ב-`data/qa/revisions.csv`) —
בעיקר חיובי ארנונה "ליתר סוגי נכס", שהגדרתם השתנתה כשנוספו סוגי נכס חדשים.

**מהדורת המדד החברתי-כלכלי בקבצי 2003–2004**: קובץ 2004 זהה ב-100% לקובץ 2005 (מהדורת 2003) ולכן
שויך למהדורת 2003; קובץ 2003 שונה (84% זהות) — מהדורה מוקדמת שאינה מצוינת, מסומנת "unspecified".

תיקון ידני: שורה ב-`etl/config/column_overrides.csv` (`year,sheet,col,indicator_id`) — או `NEW`
כדי להפריד עמודה. מזהי המדדים יציבים בין ריצות (hash של תווית העוגן).
ניסוחים חלופיים של אותו מדד: `etl/config/label_synonyms.yaml` (ניסוח בלבד — לא שינויי הגדרה).
